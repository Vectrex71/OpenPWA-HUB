# 🚀 OpenPWA Hub — The Open Static PWA Directory

A purely static, zero-server-cost directory for Progressive Web Apps (PWAs), optimized for hosting on **GitHub Pages** and static web hosts.

- 💸 **100% Free Hosting**: No backend servers, no external database subscriptions (no Supabase, no Firebase).
- ⚡ **Blazing Fast**: Pure static JSON database, instant client-side filtering, and search directly in the browser.
- 🎨 **Modern App Store Design**: Inspired by Flathub and contemporary app marketplaces with dark mode and neumorphic styling.
- 🛠️ **Automated CI/CD Pipeline**: GitHub Actions automatically validates and compiles individual app records on every git push.
- 📬 **GitHub Issues Submissions**: Friendly submission form that creates formatted GitHub issues with pre-filled JSON configurations.
- 💬 **Giscus Comments**: Community discussions and reviews powered by GitHub Discussions without third-party trackers.

## 📁 Project & Directory Structure

```text
├── .github/
│   └── workflows/
│       └── deploy.yml        # GitHub Actions CI/CD pipeline for GitHub Pages
├── apps/                     # Source directory for individual PWA definitions
│   ├── photopea.json
│   ├── excalidraw.json
│   ├── squoosh.json
│   ├── audiomass.json
│   └── ...                   # Each app is an independent JSON file
├── public/
│   ├── assets/               # Local high-resolution screenshots & icons
│   └── database.json         # Compiled master database (generated by build script)
├── scripts/
│   └── build-db.js           # Reads apps/*.json, validates schema, outputs database.json
├── src/
│   ├── components/           # UI components (Header, Hero, AppCard, Modal, etc.)
│   ├── data/                 # Fallback offline database
│   ├── types/pwa.ts          # TypeScript type definitions for PWA records
│   ├── utils/config.ts       # GitHub repository helpers & URL resolvers
│   ├── App.tsx               # Main application view with search, filter & state
│   └── main.tsx
├── package.json
└── vite.config.ts
```

## 📄 App Entry Schema (`apps/<id>.json`)

Each application is defined as an individual `.json` file inside the `/apps/` folder (for example, `apps/photopea.json`):

```json
{
  "id": "photopea",
  "name": "Photopea",
  "url": "https://www.photopea.com/",
  "description": "Advanced image and graphic editor running directly in your web browser. Supports PSD, AI, XD, RAW, Sketch, and PDF formats with layers, masks, filters, and brushes.",
  "category": "Graphics & Design",
  "tags": [
    "Offline",
    "Photo Editing",
    "PSD",
    "Vector",
    "Design",
    "Freemium"
  ],
  "iconUrl": "assets/photopea-icon.png",
  "screenshots": [
    "assets/photopea-editor.jpg",
    "assets/photopea-screenshot.jpg",
    "assets/photopea-formats.jpg"
  ],
  "youtubeVideoId": "a3aPaTNV5g4",
  "featured": true,
  "githubUrl": "https://github.com/photopea/photopea",
  "author": "Ivan Kutskir",
  "license": "Freemium / Web"
}
```

### Screenshot Ordering Convention:
- **Screenshot 1 (`screenshots[0]`):** Hero view (used for the large top showcase carousel).
- **Screenshot 2 (`screenshots[1]`):** Interface/Info view (used for the app card preview and details modal).
- **Screenshot 3+ (`screenshots[2..N]`):** Detail shots and additional features.

### Required Fields:
| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | String | Unique slug (e.g., `photopea`, lowercase letters, digits, and hyphens) |
| `name` | String | Name of the web application |
| `url` | String | Full HTTPS URL pointing to the PWA |
| `description` | String | Concise, informative summary of features and capabilities |
| `category` | String | Primary category (e.g., `Graphics & Design`, `Productivity`, `Developer Tools`) |
| `tags` | Array[String] | Keywords such as `"Offline"`, `"Open Source"`, `"Audio"`, `"Code Editor"` |
| `iconUrl` | String | Local path (in `assets/`) or HTTPS URL to high-res icon (192x192+ PNG/SVG) |
| `screenshots`| Array[String] | Array of screenshot image paths or URLs |

### Optional Fields:
- `youtubeVideoId`: 11-character YouTube video ID for embedded video trailers and walkthroughs.
- `featured`: Boolean (`true`/`false`), highlights the app in the top showcase carousel.
- `githubUrl`: Link to source code repository on GitHub (enables the GitHub button).
- `author`: Developer, studio, or team name.
- `license`: Software license (e.g., `MIT`, `Apache-2.0`, `GPL-3.0`, `Freemium`).

## 🛠️ Local Development

```bash
# 1. Install dependencies
npm install

# 2. Compile and validate database from apps/*.json
npm run build:db

# 3. Start local development server
npm run dev
```

The development server starts at `http://localhost:3000`.

## 🚀 Deployment to GitHub Pages

The included workflow `.github/workflows/deploy.yml` builds the app on every push to the `main` branch and deploys it automatically to GitHub Pages.

### One-Time GitHub Setup:
1. In your GitHub repository, open **Settings** → **Pages**.
2. Under **Build and deployment** > **Source**, choose:  
   👉 **GitHub Actions**.
3. That's it! As soon as you push a commit or merge a pull request, the action runs automatically and your site is live.

## 📬 Submitting New PWAs (1-Click Automation)

1. **Via Website:** Contributors click **"+ Submit PWA"**, fill out the submission form, and submit the pre-filled GitHub Issue.
2. **Automated Pull Request:** The GitHub Action (`.github/workflows/process-submission.yml`) automatically extracts the JSON, validates it against the schema, writes `apps/<id>.json`, and opens a **Pull Request** linked to the issue.
3. **1-Click Publish by Maintainer:**  
   - Open the generated Pull Request on GitHub.
   - Click the green **"Merge pull request"** button!
   - GitHub Actions automatically rebuilds the catalog and deploys the new PWA to GitHub Pages.

## 💬 Giscus Comments Setup

Giscus provides free, tracker-free comments powered by GitHub Discussions:
1. Ensure **Discussions** are enabled in your GitHub repository (*Settings → General → Features*).
2. Install the Giscus GitHub App via [giscus.app](https://giscus.app).
3. Set your repository in OpenPWA Hub via the Settings modal (gear icon in the header).
